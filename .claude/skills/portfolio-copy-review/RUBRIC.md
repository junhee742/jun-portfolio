# RUBRIC.md — 포트폴리오 카피 채점 계약서

`scripts/check.py` 가 기계적으로 셀 수 있는 것을 세고, 사람(또는 리뷰 에이전트)이 나머지를 채점한다.
자동 항목은 **[auto]**, 판단이 필요한 항목은 **[judge]** 로 표시한다.

기준선: 2026-08-06 실측. 총점 **24.0 / 25.0**.

## 1. 구체성 — 주장이 검증 가능한가 [auto+judge]

측정 대상은 **숫자의 유무가 아니라 검증 가능성**이다. 의미 있는 수치가 없는 일을
억지로 수치화하면 오히려 나빠진다. `AI 보완 1/1`은 숫자지만 아무것도 말하지 않고,
`518개 후보 → 대상 1개`는 "518개 중 1개밖에 못 했다"로 읽힌다.

수치를 쓸 때는 **왜 그 수치가 의미 있는지가 같이 보여야 한다.** 기준선(50%대 →
80.7%), 분모(약 100명 중), 또는 무엇이 보장되는지(이중화 후에도 중복 0건)를 붙인다.
셋 다 없으면 그 수치는 빼고 확인 가능한 사실을 쓴다.

| 점수 | 밴드 |
|---|---|
| 5.0 | 검증 불가 평가어가 없고, 랜딩 항목의 60% 이상이 의미가 드러나는 수치를 동반한다. 나머지는 수치화가 부적절해 확인 가능한 사실로 쓰였다. |
| 4.5 | 평가어 없음. 수치 동반 40% 이상. |
| 4.0 | 평가어 없으나 수치가 40% 미만. |
| 3.0 | `개선·향상·최적화·안정화`처럼 검증할 수 없는 평가어가 지표 자리에 있다. |
| 2.0 | 대부분이 일반 서술. |
| 1.0 | 수치도 고유명도 없이 형용사뿐. |

2026-08-10: 기존 규칙은 `metric:` 필드에 숫자가 있는지만 봤다. 그 결과 의미 없는
수치가 만점을 받고, 정직하게 수치를 뺀 항목이 감점됐다. 판정을 평가어 검출로 바꿨다.
| 0.0 | 어느 지원자에게나 해당되는 내용. |

**현재: 5.0** — 랜딩 10개 항목 전원 metric 보유, 전원 숫자 포함. RAG 항목은 `결과 없으면 기본 검색 fallback` 에서 `변경 경로 4곳 정적 검사·테스트` 로 바꿔 케이스 본문에 명시된 rewrite·retrieval·metadata·ingestion 4개 경로를 근거로 삼았다.

## 채점 후 할 일

1. `scripts/check.py` 를 돌려 auto 항목을 갱신한다.
2. 점수가 내려간 차원이 있으면 그 차원의 밴드 설명을 근거로 수정한다.
3. 수치를 새로 추가했으면 `docs/provenance.md` 를 먼저 갱신한다. **대장 없는 수치는 공개하지 않는다.**
