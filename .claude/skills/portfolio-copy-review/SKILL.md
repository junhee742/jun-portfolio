# 포트폴리오 카피 점검

카피 품질을 사람 감각이 아니라 **채점 계약서**로 관리한다. 문구를 고칠 때마다 같은 기준으로 다시 잴 수 있어야 회귀를 막을 수 있다.

이 저장소가 이미 AI 답변 회귀검증에서 쓰는 원리를 카피에 적용한 것이다 — 고친 것보다 **깨뜨리지 않은 것**을 확인한다.

## 구성

| 파일 | 역할 |
|---|---|
| `RUBRIC.md` | 5차원 0.0~5.0 점수 밴드. 채점 계약서. |
| `banned_phrases.json` | 기술 포트폴리오 전용 금지 패턴 + 추상명사 임계 + 도메인 예외어 |
| `scripts/check.py` | 결정론적 검사기. LLM 없이 동작. |
| `docs/provenance.md` | 근거 대장. 저장소 루트의 `docs/` 에 있다. |

## 실행

```bash
python3 .claude/skills/portfolio-copy-review/scripts/check.py
python3 .claude/skills/portfolio-copy-review/scripts/check.py --json   # 기계 판독용
```

`high` 심각도 적발이나 경계 위반이 있으면 **종료 코드 1**을 낸다. 배포 전 게이트로 쓸 수 있다.

## 작업 순서

1. **수치를 추가·변경했다면 `docs/provenance.md` 를 먼저 갱신한다.** 출처와 확인 환경을 못 채우는 수치는 공개하지 않는다.
2. 카피를 고친다.
3. `check.py` 를 돌린다.
4. `high` 적발과 경계 위반은 **전부 고친다.** 예외 없다.
5. `medium` 은 판단 항목이다. 아래 "오탐 다루기"를 읽고 결정한다.
6. `RUBRIC.md` 의 `[judge]` 항목은 사람이 채점해 점수표를 갱신한다.
7. `npm run check && npm run build` 로 마무리한다.

## 오탐 다루기 — 중요

**점수를 올리려고 좋은 문장을 망치지 마라.** 이 검사기는 휴리스틱이고, 실제로 오탐을 낸 적이 있다.

- `범위`, `조건`, `기준` 은 이 저장소에서 대부분 **의미를 지는 도메인 용어**다. `확인한 범위`는 이 포트폴리오의 정직성 장치라 줄이면 안 된다. 그래서 `abstract_noun_exempt` 목록으로 밀도 계산에서 제외한다.
- `~할 수 있습니다` 는 약한 마무리일 때만 문제다. `그 파일만 재실행할 수 있습니다` 처럼 실제 기능을 서술하면 정상이다.

패턴이 반복적으로 오탐이면 **카피가 아니라 `banned_phrases.json` 을 고친다.** 예외어를 추가하거나 패턴을 좁힌다. 그 판단을 `note` 에 남긴다.

## 절대 규칙

`AGENTS.md` 의 내용 규칙이 이 스킬보다 우선한다.

- 근거 대장에 없는 수치를 공개하지 않는다.
- 각 케이스 스터디 마지막의 경계 진술 절을 지우거나 축약하지 않는다.
- 확인 환경을 넘어서는 표현을 쓰지 않는다. 한 서비스 결과를 전체로, 내부 검증을 운영 성과로 넓히지 않는다.
- 고객사명·내부 URL·저장소명·노션 페이지 ID는 사이트에도 `docs/` 에도 쓰지 않는다. **이 저장소는 GitHub 공개다.**

점수가 이 기준선 아래로 내려가면 원인을 찾아 고친 뒤 배포한다.

## 설계 출처

공개 커리어 스킬 4종(`Paramchoudhary/ResumeSkills`, `modu-ai/cowork-plugins` 의 moai-career, `ARPeeketi/claude-resume-kit`, `daypunk/LockedIn`)을 원문 대조해 이 저장소에 맞게 재구성했다.

- 다단 채점 루브릭과 산출물별 금지어 사전 → LockedIn
- 근거 추적과 날조 금지 게이트 → claude-resume-kit 의 Provenance Flags
- 검색되는 포트폴리오, 최근 경력 비중 → moai-career

일반 자소서 금지어 사전은 이 장르에 걸리지 않는다. LockedIn 의 한국어 금지어 전체를 이 저장소 카피에 교차 검사했을 때 적발이 0건이었다. 기술 포트폴리오의 AI 문체는 어휘가 아니라 **구조의 균일함**에서 드러나기 때문에, 헤딩 중복·문두 반복·문말 편중·템플릿 절 구성을 대신 잡는다.

## 조심스러웠다는 것을 설명하지 않는다

근거를 따지는 태도는 결과물로 드러나야지, 문장으로 주장하면 자기 변호가 된다.

나쁨:
> 숫자를 이 회차에서만 가져온 이유는 단순합니다. 나머지 회차는 산출물을
> 남겨두지 않아 지금 확인할 수 없습니다. 기억으로 적을 수는 없어서 확인
> 가능한 한 건만 씁니다.

좋음:
> 한 회차를 예로 들면, 대상 선택 단계에서 나온 후보 파일은 518개였습니다.
> 테스트 작성 조건으로 거르니 새로 만들 대상은 1개가 남았습니다.

경계는 짧게 한 번 적는다. 왜 그렇게 적었는지까지 설명하면 두 배로 길어지고
방어적으로 읽힌다. `그렇게 읽히지 않기를 바랍니다`, `기억으로 적을 수는
없어서`, `정직하게 말씀드리면` 같은 표현이 신호다.

**절제는 단어 선택으로 하고, 절제한다고 알리지 않는다.** 2026-08-11에 같은
실수를 반복했다 — "접수는 확인되지 않았습니다. 다만 그것을 재발 방지 성과로
표현하지는 않습니다"라고 썼다. 뒷문장이 없어도 앞문장은 이미 성과를 주장하지
않는다. `재발을 막았습니다`와 `접수는 확인되지 않았습니다`의 차이가 절제이고,
그걸 골랐으면 거기서 끝이다.

## 헤딩을 첫 문장이 되풀이하지 않는다

목차형 헤딩을 문장형으로 바꾸면 첫 문장과 겹치기 쉽다. 헤딩이 이미 말한 것을
문장이 다시 말하면 독자는 같은 줄을 두 번 읽는다.

나쁨:
> ## 한 덩어리로 모으면 뭐가 깨졌는지 모른다
> 한 덩어리로 모으면 무엇이 깨졌는지 알 수 없습니다. 그래서 목적이 다른 질문을 따로 보관했습니다.

좋음:
> ## 한 덩어리로 모으면 뭐가 깨졌는지 모른다
> 목적이 다른 질문을 따로 보관했습니다.

## 지시어보다 지시 대상이 먼저 나온다

`두 결과`, `위 결과`, `이 방식`을 쓰기 전에 그게 무엇인지 밝힌다. 헤딩에
`두 결과`라고 써놓고 본문에서도 끝까지 이름을 안 대면, 독자는 정체를 모르는
둘이 다르다는 말을 먼저 듣게 된다.

검출:

```bash
grep -rn "^두 \|^이 두\|^위 \|^그 결과\|^이것들" src/content/work/*.mdx
```

## 이유를 모르면 비워두고 묻는다

가장 위험한 실패는 문장이 어색한 것이 아니라, **왜 그렇게 했는지를 지어내는 것**이다.
근거 문서에 없는 인과를 그럴듯하게 채우면 문서는 매끄러워지고 면접에서 무너진다.

실제로 있었던 일: "Langfuse로 노드별 응답을 볼 수 있었다"는 말을 듣고, 회귀검증에서
경로를 나눈 이유를 `한 실행에 판정이 두 개 섞여서`라고 썼다. 어디에도 없는 말이었다.

수정 전에 이 순서를 지킨다.

1. `evidence/` 와 `knowledge/` 에서 그 판단의 근거를 찾는다
2. 없으면 **비워두고 사용자에게 묻는다.** 초안을 보여주되 적용하지 않는다
3. 사용자가 준 사실만 옮긴다. 사실 사이를 잇는 논리도 확인받는다

사람에 대한 서술은 특히 조심한다. `담당자들은 AI 전담이 아니었다`처럼 남의 역량을
낮추는 문장은 사실이어도 쓰지 않는다. 같은 상황을 매체나 제약의 성질로 설명할 수 있다.

## 경계는 숫자 옆에, 면책은 쓰지 않는다

2026-08-11 이전에는 11개 사례가 전부 면책 절로 끝났다. 한 건만 읽으면 정직해
보이지만 이어 읽으면 같은 자리에서 같은 형식이 반복돼, 이 저장소가 처음에
"AI가 쓴 것 같다"고 진단했던 **구조의 균일함** 그 자체가 된다. 아무도 묻지
않았는데 매번 "이건 아닙니다"를 붙이면 변명으로 읽힌다.

세 종류를 구분한다.

**A. 범위 한정 — 반드시 남긴다.** 빼면 주장이 거짓이 되는 것들이다.
`한 서비스 기준`, `고객 운영환경에는 적용 전`, `음성은 데모까지`, `8시간은 예상
소요`. **가능하면 숫자 바로 옆에 둔다.** 절 끝으로 미루면 독자가 건너뛴다.

**B. 안 한 것의 목록 — 쓰지 않는다.** `장애 감소율도 주장하지 않습니다`,
`SLA 개선도 마찬가지입니다`. 주장하지 않는 것은 무한히 나열할 수 있고,
나열할수록 방어적이다.

**C. 비식별 고지 — 쓰지 않는다.** `고객명과 내부 주소는 공개 자료에서
제외했습니다`. 읽는 사람은 궁금해하지 않는다. 채용담당자가 아니라 감사관을
상대로 쓴 문장이다.

**전용 절은 두지 않는다.** 범위 한정은 그 주장이 나오는 문단 안에서 끝낸다.
`이 수치가 말하지 않는 것`, `여기까지가 확인한 범위`, `재색인 완료는 주장하지
않는다` 같은 절 제목은 그 자체가 신호다. 사례 끝마다 같은 성격의 절이 붙으면
읽는 사람은 내용이 아니라 형식을 먼저 본다.

절을 없애면서 그 자리에 `다만`을 다섯 번 넣은 적이 있다. 형식만 바꾸고 버릇은
남긴 것이다. 접속어를 반복하고 있지 않은지 문두 반복 검사로 확인한다.

과장 방지는 `check.py` 의 `BOUNDARY_VIOLATIONS` 가 계속 막는다. 면책 문장을
지운다고 그 장치가 약해지지 않는다.

## 구체적으로 말할 거면 앞에서 요약하지 않는다

`시간과 흔들림을 줄이는 것입니다` 뒤에 `화면을 거치면 느리고, 화면 쪽 문제로
실패해도 프롬프트가 잘못된 것처럼 보입니다`가 이어졌다. 뒷문장이 이미 다 말하고
있으므로 앞의 추상 요약은 정보를 더하지 않고 단어만 늘린다. 게다가 `흔들림`은
같은 사례 앞부분의 `같은 입력에도 같은 답이 나오지 않는다`(LLM 비결정성)와
겹쳐 읽혀 두 개념을 섞는다.

추상 명사로 먼저 묶고 나서 예를 드는 구조가 보이면, 묶은 문장을 지우고 예만
남길 수 있는지 본다. 대개 남길 수 있다.

## 면책은 절 끝에서 다시 자란다

전용 절을 없애도 각 절의 **마지막 문장**에서 되살아난다. 강한 사실로 끝나는 절일수록
반사적으로 한 줄을 덧붙이게 된다. "고객사가 직접 받았다" 뒤에 "운영환경에서 오래
지켜본 결과는 없습니다"를 붙인 적이 있는데, 앞 문장의 `사내 모델오피스`와 `확인되지
않았습니다`가 이미 범위를 말하고 있었다.

주기적으로 절 끝 문장만 훑는다.

```bash
python3 - <<'PY'
import pathlib, re
pat = re.compile(r"(없습니다|않았습니다|아닙니다|않습니다)\.?$")
for f in sorted(pathlib.Path("src/content/work").glob("*.mdx")):
    body = re.sub(r'^---.*?^---','',f.read_text(encoding='utf-8'),flags=re.S|re.M)
    for sec in re.split(r'(?=^## )', body, flags=re.M):
        if not sec.startswith("##"): continue
        paras = [p.strip() for p in sec.split("\n\n") if p.strip() and not p.startswith(("##","<"))]
        if not paras: continue
        s = [x.strip() for x in re.split(r'(?<=다\.)\s*', paras[-1]) if x.strip()]
        if s and pat.search(s[-1]): print(f.stem, "→", s[-1][:80])
PY
```

걸린 문장을 전부 지우는 것이 아니다. **판단·기능·범위 한정은 남기고, 앞 문장이 이미
말한 것을 되풀이하는 면책만 지운다.** 마지막 점검에서는 7건이 걸렸고 그중 2건만
면책이었다.
